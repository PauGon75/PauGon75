About me

I'm Pau González Cayuela, a technical game designer based in Barcelona who works where design meets code. I design gameplay systems, combat and progression, then prototype, implement and tune them myself in Unreal Engine 4/5, Unity, Godot and custom engines.

My toolkit covers game balance (modeled in Machination and Excel), game feel polish, level design and QA, backed by C#, C++ and GDScript plus Assembly. I write clear design documentation and keep teams aligned from prototype to release.

I have worked as Junior Technical Designer, Game Designer and Gameplay Programmer, and Level Designer & QA, alongside teaching review sessions in Game Mathematics and Game Programming at UPC.

Outside of work, I'm passionate about technology and development, and I love cinema and cooking. I'm also a big fan of old-school FPS shooters.

In this project I've specially learned and focused on the bridge between design and programming. How conceptual ideas can be applied onto a game framework. Doing it fast and sustainable to iterate things as soon as posible. Also, breaking down things a part to see what is actually failing and how to improve it's feeling.

"Simplicity is a great virtue but it requires hard work to achieve it and education to appreciate it. And to make things worse: complexity sells better."

Combat design and implementation

I designed and implemented a combat framework in the game. Also, making the player have reactions like knockback, making the enemies shine when hit, slowdown the combo, and so many more polishments!

Player Movement

I was in charge of making the character able to move in an isometric view, also implementing the Dash ability. And as a cherry on top, I improved the feeling via haptic design and buffers.

Map implementation

I implemented the lava map inside the engine, and creating things such as cutscenes, particles... To improve the overall experience.

Perks creation

I was in charge of designing, iterating and creating both Grapple and Torch perks. The grapple has a complex rope system that works with a sinusoidal wave of meshes that stretch themselves based on the distance that the player is from a pillar.

Polish

I did different kind of polishes in the overall game. That include: haptic polishes, time slows, some cutscene, lively grass...

Enemy Design

I designed the slime and the golem behaviours and elemental implications. All of them using flowcharts to grant a proper communication.

QA Playtest

As part of the ongoing development for Fable Of The Eclipse, a structured playtesting phase has been completed to refine the core gameplay experience.

Breakdown of the Game Engine Project

Custom C++ & OpenGL 3D Engine Architecture

A 3D game engine engineered from scratch with C++ and modern OpenGL, featuring custom scene graph management, component architecture, and real-time rendering pipelines.

This project started from scratch using C++ and the OpenGL and ImGUI libraries. It started as a simple triangle rendered on the screen and reached all the way to a full play mode.

Core Engine Features

  • On-Engine Script Editor: In-engine scripting capabilities to write, edit, and link gameplay behaviors directly within the editor environment.
  • Model Viewer: Dedicated viewport with interactive transformation tools, real-time mesh replacer, pivot adjustment, and rotation gizmos.
  • File Explorer & File Viewer: Real-time asset indexing and directory inspection for drag-and-drop asset loading.
  • Hierarchy & Inspector: Complete entity-component system (ECS) hierarchy browser and property inspection panel.
  • Scene View & Game View: Dual viewports supporting free editor camera navigation and in-game camera perspectives.
  • Renderer with Basic Lighting: Real-time rendering pipeline supporting ambient and directional lighting models, normal vectors, and Phong shading calculations.

Breakdown of the Scripting Addon

Mono Runtime & C# Integration Architecture

As our group was in charge of implementing the Scripting System, we decided to integrate Mono and use C# for scripting as Unity does.

Our system uses all of these subsystems, including Hot Reload and the Text Editor. With our Scripting System, users are able to create and manage scripts as resources, add them to the different entities and edit them within the editor.

Scripting Subsystems

  • 1. Mono Integration Subsystem: Manages the initialization of the Mono runtime and the communication between C++ and C#.
  • 2. Script Resource and Importing Subsystem: Treat scripts as engine resources.
  • 3. Script Component Subsystem: Allow engine entities to have C# logic attached.
  • 4. C++ & C# Binding Subsystem: Expose engine functionality to scripts.
  • 5. Script Serialization Subsystem: Allow public script variables to be saved within scenes or prefabs.
  • 6. Script Editor Subsystem: Provide in-engine script editing tools.
  • 7. Script Compilation Subsystem: Compile .cs files into .dll assemblies.
  • 8. Hot Reload Subsystem: Reload scripts without restarting the engine.

Example: the tank script

You can see an example of the functionalities in the tank script. With this script you can move a tank with the keyboard and rotate the turret with the mouse around the scene. The tank shoots bullets (which are new entities).
